# 3D 에셋 파이프라인

그래픽은 **3D**로 확정했다. 에셋 제작은 **VARCO 3D**로 한다.

7일 일정에서 3D의 가장 큰 위험은 폴리곤 수도 렌더링 비용도 아니고, **에셋이 안 나와서 개발이 멈추는 것**이다. 이 문서의 절반은 그걸 막는 규칙이다.

## 1. 그레이박스 우선 — 에셋을 기다리지 않는다

**1~5번 묶음은 프리미티브로 개발하고, 에셋은 작업 6.6 에서 끼워 넣는다.**

- 코인 = `Cylinder`, 망치 = 길쭉한 `Cube`
- 타격 대상 4종은 모양과 색으로 구분한다 — 일반 `Cube` / 거치 `Cylinder` / 고속 `Sphere` /
  회복 `Capsule`, 머티리얼 4개. **회복형을 빠뜨리지 않는다** — 부수면 스태미나를 돌려주는
  대상이라 한눈에 구분돼야 한다 (GDD 4절)
- 이 상태로 **작업 2.6 완주 빌드까지 간다.** 박스가 돌아다니고 커서를 올리면 코인이 튀어나오면 게임은 완성된 것이다. 예쁜 건 나중 문제다

교체가 재작업이 되지 않으려면 프리팹 구조를 지금 정해야 한다.

### 프리팹 구조 규칙 (필수)

```
Piggy_Normal (프리팹 루트)
├─ [로직]  Collider, PiggyController, IHittable 구현     ← 코어 플레이 담당 소유
└─ Visual  (빈 GameObject)                                ← UI·연출 담당 소유
   └─ <모델명>  ← Renderer 를 가진 모델 자식. 그레이박스 시절엔 Cube 였고 지금은 MineCreature{X}
```

- `Visual` 아래 자식 **이름은 고정하지 않는다** — 어떤 프리팹에 어떤 모델이 붙었는지 이름으로 구분되는
  편이 낫다. 검증(`TargetChecks`)은 "Visual 은 비어 있고, 그 아래 Renderer 를 가진 자식이 있다"만 본다 (#287).

- **로직 컴포넌트는 루트에만 붙인다.** 메시 오브젝트에 직접 붙이면 교체할 때 같이 날아간다.
- 콜라이더도 루트에 둔다. 모델이 바뀌어도 판정 크기는 그대로여야 밸런스가 유지된다.
- 교체는 `Visual` 아래 자식을 갈아끼우는 것으로 끝나야 한다. 이 조건이 지켜지면 **에셋 교체가 코어 담당자의 작업을 건드리지 않는다.**
- 스크립트에서 메시를 참조할 일이 있으면 `Visual` 트랜스폼까지만 참조한다 (스쿼시&스트레치는 `Visual`을 스케일한다 — 루트를 스케일하면 콜라이더까지 커진다).

## 1-1. 원작 아트 레퍼런스 — 어디서 보고, 무엇을 하면 안 되나

색감·조명·저금통 형태·책상 연출을 확인할 때 쓴다. **출처는 개발사 공식 프레스킷이다.**

- **프레스킷**: <https://rikegames.com/press/bills-must-be-paid/>
  스크린샷 9장(1920x1080), 키아트(저금통 캐릭터 투명 PNG), 로고·캡슐, 트레일러, 레이어 PSB 까지 있다.
  없는 것은 `info@rikegames.com` 으로 요청하면 보내 준다고 적혀 있다 (UI 없는 스크린샷, 인쇄 해상도 키아트 등).
- **Steam 스토어**: <https://store.steampowered.com/app/4421010/_Bills_Must_Be_Paid/>
- **공식 게임 페이지**: <https://rikegames.com/bills-must-be-paid>

### 내려받은 것은 저장소에 넣지 않는다

`research/reference/press-kit/` 에 두고 **gitignore 로 막아 두었다.** 자막 원본(`research/transcripts/`)과 같은
취급이다 — **타인의 저작물이라 커밋하지 않는다.**

프레스킷은 **보도용으로 제공된 자산**이다. 기사·리뷰에 싣는 용도로 허락된 것이지, 다른 게임에
넣으라고 준 것이 아니다. 그래서 이렇게 가른다.

| 해도 되는 것 | 하면 안 되는 것 |
|---|---|
| 화면을 띄워 놓고 **보면서** 우리 에셋을 만든다 | 이미지를 잘라 우리 게임에 **넣는다** |
| 색·명도·구도·비율을 **재서** 수치로 옮긴다 | 저장소에 **커밋**한다 |
| 문서에 "원작은 이렇다" 를 **글로** 적는다 | 로고·캡슐을 우리 홍보물에 쓴다 |

**로고와 Steam 캡슐은 아예 받지 않았다.** 브랜딩 자산이라 우리가 쓸 일이 없고, 받아 두면
누군가 쓰게 된다.

### 수치를 옮길 때

게임 내 툴팁 수치는 **등급 A(직접 관찰)** 근거다. 다만 **기본값인지 강화값인지 확인한다** —
`악력` 스킬을 찍은 뒤의 툴팁을 기본값으로 착각해 `stamina.csv` 에 잘못 넣은 적이 있다
([REFERENCE_ANALYSIS.md](REFERENCE_ANALYSIS.md) "원작 기본 망치 툴팁" 절).

## 2. VARCO 3D 사용 규칙

### 먼저 확인할 것 (킥오프)

VARCO 3D 의 출력 사양을 팀에서 한 번 확인하고 아래를 채운다. 확인 전에는 에셋을 여러 개 만들지 않는다 — **기준 없이 10개 만들면 10개를 다시 만들어야 한다.**

- [x] 내보내기 포맷 (`.glb` / `.fbx` / `.obj`) 및 Unity 임포트 시 이상 유무 — `.glb` 사용. `com.unity.cloud.gltfast` 패키지 설치 후 정상 임포트 확인 (`Transform`/`MeshFilter`/`MeshRenderer` 구성, 저금통 일반형 실측)
- [x] 폴리곤 수 조절 가능 여부 — 목표는 저금통 1체당 **1,000~2,000 삼각형**. `Generate3D` 노드의 `polygonCount` 파라미터로 지정 가능, 저금통 일반형 실측 1,500삼각형으로 확인
- [x] 텍스처 해상도 — **1024×1024(BaseColor)/2048×2048(Normal) 그대로 사용한다.** glTFast(`com.unity.cloud.gltfast`)로 임포트한 텍스처는 Unity의 `TextureImporter` Max Size 설정이 적용되지 않는다 (glTFast는 자체 임포터를 쓰며 리플렉션으로 확인한 `ImportSettings`/`InstantiationSettings`/`EditorImportSettings` 어디에도 해상도 조절 필드가 없음). 512 다운스케일은 별도 `AssetPostprocessor`가 필요해 배보다 배꼽이 커짐 — 저금통 1개당 VRAM 약 26MB(BaseColor+Normal, 밉맵 포함)로 예산에 문제없어 그대로 채택
- [x] 머티리얼이 URP 셰이더로 들어오는지 (Built-in 셰이더로 들어오면 분홍색으로 보인다 → `Edit > Rendering > Materials > Convert...` 로 일괄 변환) — glTFast가 `Shader Graphs/glTF-pbrMetallicRoughness` 셰이더로 임포트, 현재 파이프라인(URP)에서 `isSupported=true` 확인. Built-in 셰이더 아니므로 변환 불필요
- [x] 생성물의 이용 조건 — 수업/포트폴리오/공개 배포 각각 가능한지 ([THIRD_PARTY.md](THIRD_PARTY.md)에 기록). NC AI 교육 프로그램 하 수업 프로젝트 용도로 사용 가능, 공개 배포·상업적 이용은 별도 확인 필요

### 스케일 기준

**타격 대상 높이를 0.65 유닛으로 통일한다.** 기준은 미터가 아니라 **확정된 카메라 구도**와
**조준 원(`economy.csv` 의 `reticle_radius=0.45`, 지름 0.9유닛) 대비 크기**다.

이 값은 실물 크기가 아니라 화면에서 차지하는 비율로 정했다. 확정된 카메라(작업 1.1.3 —
Perspective, FOV 45, 높이 5.64, 내려보기 46.9°)에서 책상 평면의 보이는 세로 범위는 약 6.4 유닛이고,
`DeskPlane_Greybox` 자체가 6×6 유닛이다.

> **이전 기준(0.8 유닛)은 쓰지 않는다.** 작업 6.6 에서 광물 크리처로 교체하며 조준감을 위해 올린
> 값인데, 6.26 씬 배치(#239)에서 소품 14종이 가장자리를 채운 뒤 크리처 이동 영역
> (4.8×4.8, `CreatureManager._deskBounds`)이 상대적으로 좁아 이동이 답답하다는 피드백이 있었다.
> 조준 원 대비 크기를 83% → 약 67% 로 낮춰 이동감을 확보했다 — 여전히 원 안에 들어오는 크기다.
>
> **그 이전 기준(0.4 유닛)은 쓰지 않는다.** 저금통(#9)에서 정한 값인데, 작업 6.6 에서 광물 크리처로
> 교체한 뒤 실측해 보니 조준 원(지름 0.9유닛)보다 눈에 띄게 작아 조준감이 떨어졌다 — 발주 배경은
> [광물 크리처 에셋](TECH_NOTES/mineral-creature-assets.md) 참고.
>
> **가장 이전 기준(0.12 유닛 = 12cm)도 쓰지 않는다.** 같은 카메라에서 화면 세로의 1.9%,
> 1080p 기준 세로 20픽셀밖에 안 돼 조준이 성립하지 않는다. 카메라가 확정되기 전에 적힌 값이라
> 구도를 반영하지 못했다. 1유닛=1미터로 읽으면 책상이 6m가 되므로 **미터 환산은 하지 않는다.**

모델마다 크기가 제각각이면 카메라와 이동 속도, 콜라이더 크기가 전부 어긋난다.

> **정정 (glTFast 사용 확인 후)**: 이 절은 원래 FBX `ModelImporter`의 `Scale Factor`를 전제로 썼다. 이 프로젝트는 `.glb`를 glTFast로 임포트하는데, glTFast 임포터에는 전역 스케일 필드가 없다 (리플렉션으로 `ImportSettings`/`InstantiationSettings`/`EditorImportSettings` 전 필드 확인 완료). 대신 **1절 프리팹 구조 규칙이 이미 정해 둔 대로 `Visual` 자식만 스케일한다** — 루트(콜라이더)는 그대로 두므로 판정 크기와 파편 물리 거동은 영향받지 않는다. 저금통 일반형은 `PiggyNormalVisual.prefab`(Visual 루트, `localScale ≈ 0.476`, 높이 0.4유닛 기준. 이후 광물 크리처로 교체되며 폐기)로 분리 제작했었다. 광물 크리처 4종은 모델마다 원본 크기·피벗이 달라 `Renderer.bounds` 를 직접 측정해 높이 0.8유닛에 맞는 스케일·바닥 오프셋을 모델별로 계산했다 — 수치는 [광물 크리처 에셋](TECH_NOTES/mineral-creature-assets.md) 참고.

**피격 판정 반경은 이 크기에서 재지 않는다.** 모델이 바뀌어도 판정이 그대로여야 밸런스가 유지되므로,
반경은 프리팹 루트에 고정값으로 두고 `economy.csv` 의 `hit_radius_bonus` 만 곱한다 (1절).

## 3. 파손 표현

원작은 타격할수록 저금통에 금이 누적되다가 파괴된다. 모델을 단계별로 여러 개 만들 필요는 없다.

- **크랙 텍스처를 머티리얼에 얹고 HP 비율에 따라 알파를 올린다.** 모델은 하나면 된다.
- 파괴 순간에만 원본을 끄고 파편 프리팹을 켠다. 파편에는 리지드바디를 붙여 물리로 흩어지게 둔다.
- 파편은 3초 뒤 사라지게 한다 — 바닥에 계속 쌓이면 드로우콜이 늘고 화면이 지저분해진다.

## 4. 성능 예산

[ARCHITECTURE.md](ARCHITECTURE.md) 5절의 예산을 3D 기준으로 구체화한 것이다.

- 드로우콜 **200 이하**, 화면 내 삼각형 **15만 이하**
- **그림자를 드리우는 것은 타격 대상만.** 파편·코인은 `Cast Shadows = Off` — 동시 50개가 그림자를 드리우면 그것만으로 프레임이 무너진다
- 파편과 코인은 오브젝트 풀에서 꺼내 쓴다 ([PATTERNS.md](PATTERNS.md) 7절)
- 라이트는 **Directional 1개 + 앰비언트**로 시작한다. 포인트 라이트를 저금통마다 붙이지 않는다
- 작업 7.1 프로파일링에서 위 수치를 실측한다. "느낌상 괜찮다"로 판단하지 않는다

## 5. 커밋 규칙

- 3D 모델·텍스처는 바이너리라 Git 이력에 누적된다. **같은 파일을 여러 번 덮어쓰며 커밋하지 않는다** — 최종본이 나온 뒤 한 번에 올린다
- 파일이 커지면 `.gitattributes` 의 LFS 섹션 주석을 해제한다 (전원 `git-lfs` 설치 필요)
- 에셋을 추가한 PR에서 [THIRD_PARTY.md](THIRD_PARTY.md) 표를 같이 갱신한다
