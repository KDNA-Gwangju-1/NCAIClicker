## 3. 그래픽 — 원작은 3D다

Steam 태그에 `3D`가 명시되어 있고, 실제 게임 화면에서도 확인된다.

직접 관찰한 내용:

- 책상이 원근으로 물러나는 **고정 카메라**. 직교 투영이 아니다.
- 저금통은 스프라이트가 아니라 **3D 메시**다. 각자 바닥에 실시간 그림자를 드리운다.
- 망치와 손이 3D 모델이며 화면 안쪽 방향으로 스윙한다.
- 타격하면 저금통에 **금이 간 상태가 누적**되고, 파편이 튀어 바닥에 남는다.
- 코인이 튀어올라 굴러다니다 책상 위에 정지한다. 물리 기반 낙하로 보인다.
- 창밖 네온과 라디오 등 **3D 환경 소품**으로 분위기를 만든다.

초기 기획서는 "2D 스프라이트 기반"으로 작성되어 원작을 잘못 파악했다. 현재 GDD는 3D 저폴리 메시와 고정 원근 카메라로 수정되어 있다.

### 왜 이게 중요한가

리뷰가 공통적으로 꼽는 이 게임의 재미는 **"부수는 손맛"** 이다 — 타격감, 효과음, 시각적 충격. 그 손맛의 상당 부분이 3D에서 거의 공짜로 나온다.

| 연출 | 3D에서 | 2D 스프라이트에서 |
|---|---|---|
| 파손 단계 누적 | 메시 교체 또는 크랙 텍스처 | 단계별 스프라이트를 전부 그려야 함 |
| 파편 비산 | 리지드바디 파편 프리팹 | 파편 스프라이트 + 수동 궤적 |
| 코인이 굴러 쌓임 | 물리로 자동 | 프레임별 애니메이션 필요 |
| 그림자·입체감 | 라이트 하나 | 그림자까지 그려야 함 |
| 타격 반응 | 스쿼시&스트레치 스케일 | 동일하게 가능 |

**2D가 싼 게 아니다.** 2D가 싼 것은 그림을 그려줄 사람이 있을 때다. 우리 역할 분담표에 아티스트가 없다 — UI·연출 담당은 원화가가 아니다. 스프라이트를 직접 그리거나 사올 사람이 없는 상태에서 2D를 고르면, 결과물은 "단순한 2D"가 아니라 **"연출이 빈 2D"** 가 되기 쉽다.

반면 3D는 프리미티브에 가까운 저폴리 모델 하나와 라이트 하나로도 그림자와 입체감이 나오고, 파편·코인은 물리에 맡길 수 있다.

### 결정: 3D (고정 탑다운 카메라) — 확정됨

3D 에셋은 **VARCO 3D 로 생성**하기로 했다. 아티스트가 없다는 제약이 해소되어, 위 표의 이점을 그대로 가져갈 수 있다. 제작 절차는 [ASSET_PIPELINE.md](ASSET_PIPELINE.md) 참고.

원작과 동일하게 **3D 에셋을 고정 탑다운 카메라로 렌더링**한다.

- 저금통·코인·망치·파편 모두 저폴리 3D 메시다. **스프라이트나 빌보드는 쓰지 않는다.**
- 카메라는 고정. 타격 대상이 책상 평면(XZ) 위에서만 움직이므로 **이동·판정 연산이 2축으로 끝난다** — 표현이 아니라 연산 얘기다. 이 덕분에 기존 기획의 이동·피격 규칙을 거의 그대로 쓸 수 있다.
- 커서는 스크린 좌표를 책상 평면으로 레이캐스트해 위치를 구한다.
- 파편과 코인만 물리를 쓴다. 타격 판정과 자동 망치는 물리를 쓰지 않는다 (타이머 기반 설계 그대로 유효).

### 이 결정이 바꾸는 것

아래 항목이 함께 바뀐다. 각자 작업을 시작한 뒤에 바꾸면 전부 재작업이므로 작업 1.2.1 이전에 확정했다.

| 문서·설정 | 기존 | 확정 내용 |
|---|---|---|
| GDD 1절 그래픽 | 2D 스프라이트 | 3D 저폴리 + 고정 탑다운 카메라 |
| GDD 4절 피격 판정 | 콜라이더 25% 확대 | `Collider2D` → `Collider`(3D), 또는 스크린 거리 기반 판정 |
| GDD 4절 이동 영역 | 화면 상하좌우 10% 여백 | 책상 평면의 경계 박스 |
| GDD 7절 연출 | 스프라이트 스쿼시&스트레치 | 유지 + 파편·그림자 추가 |
| ARCHITECTURE 5절 | 파티클 오버드로우 점검 | 드로우콜·섀도우 캐스터·메시 배칭 점검으로 변경 |
| URP 렌더러 | 2D Renderer 도입 여부 검토 중 | **기본(3D) 렌더러 유지** — 결정 완료 |
| 커서 입력 | 스크린 좌표 직접 사용 | 평면 레이캐스트 |

### 남는 위험

3D로 간다고 해서 공짜는 아니다. 아래 둘은 실제로 발생할 수 있다.

- **에셋 대기로 개발이 멈추는 것** — VARCO 3D 출력이 늦어지면 코어 작업이 멈춘다. 그래서 그레이박스로 먼저 완주시키고 에셋은 나중에 끼워 넣는다 ([ASSET_PIPELINE.md](ASSET_PIPELINE.md) 1절).
- **드로우콜과 그림자 비용** — 동시 8마리에 파편까지 더해지면 2D보다 렌더링 부담이 크다. 그림자 캐스터를 제한하고 작업 7.1 프로파일링에서 실측한다.

## 4. 스킬 트리 — 확인됨

등급 A 출처 두 곳에 모두 명시되어 있다.

- Steam 스토어 페이지: 여러 업그레이드 경로를 가진 스킬 트리
- 개발사 프레스킷: "분기형 스킬 트리(branching skill tree)"로 명시하며 항목을 나열 — **악력(grip strength), 카페인 중독(caffeine addiction), 헬스장 훈련(gym training), 손목 강화(wrist enhancement), 행운(luck), 돌 비(rock rain), 망치 전기화(hammer electrification)**

우리는 이를 업그레이드 4종(분기 없는 선형)으로 축소했고, 그 판단 자체는 7일 일정상 타당하다. 다만 **축소하면서 같이 잃은 것이 하나 있다.**

리뷰들은 스킬 트리를 성장 장치가 아니라 **유머 장치**로 언급한다. "카페인 중독"이나 "망치 전기화" 같은 이름이 주는 웃음이 반복적인 루프를 한동안 버티게 해준다는 평가다. 반대로 그 유머가 떨어지는 지점에서 반복성이 드러난다는 지적도 같은 리뷰에 있다.

**적용함.** 업그레이드 이름을 기능 설명에서 원작 톤으로 바꿨다. 기능과 수치는 그대로이므로 밸런스에는 영향이 없다.

| id | 기존 | 변경 | 효과 (그대로) |
|---|---|---|---|
| `strong_hammer` | 강한 망치 | **악력 단련** | 타격 파워 +0.35 / 판정 반경 +2% |
| `auto_hammer` | 자동 망치 | **카페인 중독** | 자동 망치 +1기 |
| `fever_boost` | 피버 강화 | **헬스장 회원권** | 피버 지속 +0.5초 / 배율 +0.2 |
| `desk_expand` | 대상 증가 | **저금통 수집벽** | 동시 출현 +1기 / 재등장 대기 -6% |

원작의 grip strength / caffeine addiction / gym training 을 우리 효과에 맞게 옮긴 것이다. "카페인 중독"이 자동 망치가 된 것은 **손이 저절로 떨려서 안 때리려 해도 때려진다**는 설명이 자동 타격과 맞아떨어지기 때문이다.

이름과 설명은 `upgrades.csv` 의 `display_name` / `description` 두 칸에만 있으므로, 톤이 마음에 안 들면 그 두 칸만 고치면 된다.

> 스킬 트리의 **분기 구조** 자체는 도입하지 않는다. 분기는 밸런싱 대상이 배로 늘고, 4종 선형 구조로도 성장의 체감은 충분하다.

## 5. 스태미나와 망치 — 확인 완료

한때 1차 출처가 엇갈리는 것처럼 보였던 항목이다. **직접 확인으로 해소됐다.**

| 출처 | 내용 |
|---|---|
| Steam 스토어 페이지 · 개발사 프레스킷 | *"Smashing costs stamina. When your hand is getting tired the run is over."* — 타격이 스태미나를 소모한다 |
| 팀원의 직접 플레이 확인 | 저금통이 없는 빈 곳에 커서를 두고 마우스를 멈춰도 **게이지가 계속 감소**한다. 그리고 **망치 타격 모션이 대상 유무와 무관하게 계속 반복 재생된다** |

두 관찰은 모순이 아니다. **망치는 항상 스윙하고 있다.** 그러므로 "스윙이 스태미나를 소모한다"는 개발사 설명은 사실이고, 스윙 빈도가 일정하므로 **결과적으로 시간 기반과 동일하게 닳는다.** 둘 다 맞는 말이었다.

### 이것이 바꾸는 것 — 조작의 본질

이 발견은 단순한 수치 문제가 아니다. **플레이어가 하는 일이 "타격"이 아니라 "조준 유지"라는 뜻이다.**

- 망치는 커서 위치와 상관없이 **항상** 일정 주기로 스윙한다.
- 커서를 대상 위에 올리는 행위는 스윙을 *시작하는* 것이 아니라, 이미 진행 중인 스윙이 **무엇을 맞힐지 고르는** 것이다.
- 빗나간 스윙도 스태미나를 쓴다. 그래서 **아무것도 안 맞히고 흘려보낸 시간이 곧 손해**다.

우리 기획서의 "커서를 올리면 자동으로 타격한다"는 표현은 이 구조를 정확히 담지 못했다. GDD 4절을 "망치는 상시 스윙하며, 커서는 그 스윙이 닿을 대상을 고른다"로 고쳤다.

### 우리의 결정: 시간 기반 감소

원작과 동일하게 **초당 지속 감소**를 쓴다. 구현은 스윙마다 스태미나를 깎는 대신 초당 감소로 단순화한다 — 스윙 주기가 고정이면 두 방식의 결과가 같기 때문이다.

- **회복을 제외한 기본 런 길이를 통제한다.** 최대 스태미나와 초당 감소량으로 기본 길이를 정하며, 회복형·퍼크가 실제 런을 연장한다. 7일 안에 밸런싱을 끝내야 하는 입장에서 이 예측 가능성이 크다.
- **규칙 설명이 한 줄로 끝난다.** 이동·타격 소모가 있으면 "왜 빨리 끝났지?"를 플레이어가 추론해야 한다.
- **구현이 단순하다.** 이동 거리 누적과 타격 카운트를 스태미나에 연결할 필요가 없다.

대신 잃는 것도 명확히 적어둔다. **"이동은 공짜가 아니다"라는 판단이 사라진다.** 그래서 타격 대상 4종의 존재 이유가 "이동 비용 대비 가치"에서 **"제한된 시간 대비 가치"**로 옮겨간다 — 오래 걸리지만 비싼 거치형을 칠지, 빨리 부서지는 일반형을 칠지의 판단은 여전히 성립한다. 약해지지만 무너지지는 않는다.

> 나중에 되돌릴 수 있도록 `move_drain_per_unit` 과 `hit_drain_per_swing` 필드는 **0으로 두되 삭제하지 않는다.** 현재 임포터는 0 이외 값을 거부한다. 행동 기반 소모를 도입하려면 규칙·검증부터 함께 변경한다.

## 6. 공식 게임 페이지에서 추가 확인한 사항

개발사 공식 게임 페이지를 뒤늦게 확인했다. 앞서 논쟁했던 항목들이 여기서 정리된다.

### 데모와 정식판을 구분한 정정 (2026-09-16)

기존 분석은 공식 게임 페이지의 데모 추심 설명을 정식판에도 적용해 GDD의 즉시 파산을 오류로 판단했다.
**이는 버전 구분 누락이었다.** [개발자 출시일 발표](https://www.reddit.com/r/playmygame/comments/1u6m0jv/youre_broke_smash_piggy_banks_bills_must_be_paid/)는 데모의 수입 삭감과 정식판의 미납 파산·재시작을 명시적으로 구분한다.
[현재 Steam 정식판 설명](https://store.steampowered.com/app/4421010/Bills_Must_Be_Paid/)도 미납 파산과 납부 보상·레거시 포인트를 설명한다.
반면 [개발사 게임 페이지](https://rikegames.com/bills-must-be-paid)는 아직 출시 예정·데모·추심 문구를 함께 싣고 있다.

| 비교 | 원작 확인 | 우리 결정과 이유 |
|---|---|---|
| 미납 | 데모: 수입 삭감. 정식판 발표: 파산 후 재시작 | **즉시 파산 유지**. 추심 누적 카운터·추심 삭감률은 추가하지 않는다 |
| 파괴 보상 | 공식 페이지는 대상 파괴 시 드랍을 명시 | 파괴 즉시 장부 반영. 바닥 코인은 연출이며 종료 시 중복 입금하지 않는다 |
| 퍼크 | 개발자 발표에서 3개 중 1개 선택 확인 | 선택 중 시간 정지, 결과에서 고른 효과는 다음 런 예약. 이 타이밍은 원작 미확인인 **우리 구현 결정** |
| 저장 | Steam Cloud 지원 확인. 정확한 자동 저장 시점은 미확인 | 회차 상태를 함께 저장하고 런 도중 종료는 시작 스냅샷으로 복귀 |
| 소수 코인 | 원작 내부 반올림 방식 미확인 | decimal 누적, 정수 입금, 잔여 저장으로 작은 보상 소실 방지 |

공식 페이지로 확인한 시간 기반 스태미나·The Tourist의 파괴 회복·종류별 드랍은 유지한다.
문서에서 과거에 언급한 미납 허용 횟수·파산 반액 정산은 현재 MVP 규칙이 아니며 CSV에 추가하지 않는다.
대출의 수입 징수는 별도 규칙으로 유지한다 (바로 아래 절에서 원문으로 확정했다). 납부 횟수에 따른 레거시·장신구 성장은 MVP에서 제외한다.

### 확정 — 빅 토니 징수는 대출이 있을 때만 발생한다

정산 화면의 "Tony's cut" 을 **상시 수수료로 오해하기 쉽다.** 정산창 스크린샷만 보면 매 정산마다
10% 를 떼는 고정 항목처럼 보이기 때문이다. 실제로 그렇게 단정했다가 틀린 적이 있다.

게임 내 안내문을 소리 내어 읽는 구간(등급 A)이 원문으로 못 박는다.

> Take 410 out at 10%. You owe 451.
> **Tony takes 5 to 10% of your earnings every day until you repay the loan.**
> **That cut does not reduce your debt.** Once you pay it back, Tony won't lend again for 5 days.
>
> — `TUelRO1J0Vg.txt` 70:15–70:27

같은 영상 71:24 에서 플레이어가 "What do you mean Tony's cut? 1,500. I only owe Tony 450." 라며
정산창의 해당 항목을 읽는데, **이때 그는 빚이 있는 상태다.** 화면 우상단에도 남은 빚이 함께 표시된다.

| 원작 규칙 | 근거 | 우리 `bills.csv` |
|---|---|---|
| 상환 전까지 매일 수입의 5~10% 징수 | 위 원문 | `loan_daily_cut_min` 0.05 / `loan_daily_cut_max` 0.10 ✅ |
| 징수분은 부채를 줄이지 않는다 | 위 원문 | 주석에 동일 명시 ✅ |
| 완제 후 5일간 재대출 불가 | 위 원문 | `loan_cooldown_days` 5 ✅ |
| 이자 10% | 위 원문 (410 → 451) | `loan_interest_rate` 0.10 ✅ |

**우리 CSV 는 이미 원작과 같다.** 그러므로 정산 화면의 징수 항목은 **대출이 있을 때만 보여야 한다.**
빚이 없는데 항목이 떠 있으면 원작과도 우리 규칙과도 어긋난다.

부수적으로 확인된 것: 원작에는 "after borrowing, Tony skips his cut for one day" 퍼크가 있다
(`TUelRO1J0Vg.txt` 97:55). 우리 `perks.csv` 에는 없으며 MVP 범위 밖이다.

### 새로 드러난 것 — 저금통 6종과 각자의 역할

공식 페이지가 저금통 종류를 이름과 특성까지 밝힌다. 우리가 프레스킷의 "도망/정지/고액" 세 축으로 추측했던 것보다 구체적이다.

| 이름 | 특성 | 플레이 영상 확인 |
|---|---|---|
| Normalito | 표준. 안정적인 수입 | ✅ 등장 |
| **The Tourist** | **부수면 스태미나를 회복시킨다** | ✅ 등장 |
| Woody | 느리게 움직이고 단단하다 | ❌ **0회** |
| Piñata | 보상 편차가 크다 (고위험 고수익) | ❌ **0회** |
| El Loco | 예측 불가능하게 빠르게 움직인다 | ❌ **0회** |
| (희귀종) | 진행하면서 해금 | — |

**이름이 두 출처에서 어긋난다.** 위는 공식 페이지 기준이고, 플레이 영상 자막에는 `Woody`·`Piñata`·`El Loco`
가 **한 번도 나오지 않는다.** 대신 아래 이름들이 나온다. 어느 쪽이 틀렸다고 단정할 근거는 없다 —
공식 페이지가 출시 전 데모 기준일 수 있고(0절 주의사항), 자막이 후반 해금종만 담았을 수도 있다.

| 자막에서 확인된 이름 | 게임 내 설명 | 출처 |
|---|---|---|
| Viking | *"Brave, tough, and hard to smash. A lot of money."* · HP 4배 | `TUelRO1J0Vg.txt` 168:00, 150:34 |
| Balito | (설명 미확인) | `TUelRO1J0Vg.txt` 70:57 |
| Golden pig | (설명 미확인, 고가치로 보임) | `TUelRO1J0Vg.txt` 71:56 |

`Viking` 은 표의 "(희귀종) 진행하면서 해금"에 해당할 가능성이 높다. **즉 종류는 6종보다 많고 후반 해금형이 있다.**

우리 4종 매핑 중 **거치형↔Woody, 고속형↔El Loco 는 자막으로 뒷받침되지 않는다.** 역할 대응은 유효하나
이름을 근거로 인용하지 않는다. 우리 저금통의 외형은 우리 에셋으로 간다 (이름·역할은 `targets.csv` 가 정본).

**`The Tourist` 가 이 게임 설계의 핵심 장치다.** 스태미나가 시간 기반이면 런 길이가 고정되어 판단할 것이 줄어드는데, **스태미나를 회복시키는 대상이 섞여 있으면 "런을 연장하려면 저놈부터 쳐야 한다"는 우선순위 판단이 생긴다.** 우리가 이동 비용을 없애면서 잃은 긴장을 정확히 그 자리에 메워 넣는 장치다.

### 기타

- 스킬 트리 분기: *"Grip, caffeine, gym, wrist, luck"* + *"Weirder stuff opens up deeper in"*
- 망치: damage, swing speed, crit chance, hit radius 네 축
- 분량 평가: 리뷰들은 2~3시간이면 신선함이 떨어진다고 본다. 우리 3단계 구성은 이 범위 안에서 타당하다

## 7. 검토했으나 도입하지 않은 시스템

플레이 영상 전체를 훑어 확인된 원작 시스템 중, **의도적으로 빼기로 한 것**들이다. 나중에 "이건 왜 없죠?"라는 질문이 나왔을 때 답이 되도록 이유를 남긴다.

| 시스템 | 원작 내용 | 도입하지 않는 이유 |
|---|---|---|
| 콤보 | 연속 적중이 쌓이면 보너스 | 피버와 역할이 겹친다. 둘 다 "연속으로 잘 맞히면 보상"이다 |
| 프레스티지 · 레거시 포인트 | 청구서에 쓴 금액 50당 1포인트. 프레스티지해도 링과 코인 컬렉션은 유지 | 이중 화폐를 만들지 않기로 했다 |
| 특수 효과 업그레이드 | 테이블 스파이크, 충격파, 번개, 팬텀 핸드, 코인 복제 | 업그레이드 4종 구조를 유지한다. 밸런싱 대상이 배로 는다 |
| 코인 컬렉션 | 희귀 코인 도감 | 수집 요소는 MVP 밖 |
| 해머 상점 · 도박 미니게임 | 성능이 다른 해머 구매, 슬롯머신과 더블오어낫싱 | **추가 목표로 유지.** 리뷰들이 운 의존을 불만으로 꼽으므로 우선순위는 낮게 |

> 프레스티지를 빼면서 같이 놓친 관점이 하나 있다. 원작에서 **청구서 납부액은 곧 영구 성장 자원**이다 — 청구서가 벌금이 아니라 투자다. 우리 설계에서 청구서가 순수 손실로만 느껴진다면, 납부 퍼크를 조금 더 후하게 잡아 이 감각을 흉내낸다.

## 8. 참고 — 원작의 청구서 금액 곡선

플레이 영상에서 관찰된 순서: 750 → 1,000 → 5,800 → 12,000 → 65,000 → 250,000

배율이 일정하지 않고 **후반으로 갈수록 급격히 뛴다.** 우리 초기 단계 목표는 economy.csv의 성장률을 기준으로 산출해 stages.csv에 저장한다. 실제 단계 목표와 청구 금액은 CSV를 확인한다. 3단계가 너무 쉽게 느껴지면 마지막 단계만 배율을 올리는 방식을 검토한다.

## 9. 남은 미확인 항목

아직 1차 출처로 확인하지 못한 것. 필요해지면 그때 원작 플레이로 확인한다.

- 저금통별 정확한 내구도·코인 값
- 퍼크 선택 중 시간 정지 여부·결과 화면 수령 효과의 발동 시점 (3개 중 1개 선택은 개발자 발표로 확인)
- 피버에 해당하는 시스템이 원작에 있는지 — **우리 고유 요소일 가능성이 높다**
