# 착수 가능한 이슈 목록

`AGENTS.md` 의 **"작업 흐름 (요약)"** 이 판정 규칙의 정본이다. 여기에는 실행 방법만 적는다.

판정 기준은 두 가지뿐이다.

- 보드의 **Status 가 `Todo`** 일 것
- 이슈 본문 `**선행**:` 에 적힌 이슈가 **전부 닫혀 있을** 것

**담당자(assignee)는 판정에 쓰지 않는다.**

## 1. 보드에서 Status 를 읽는다

```bash
gh project item-list 2 --owner KDNA-Gwangju-1 --limit 200 --format json
```

`gh issue list` 만으로 판정하지 않는다. Status 는 이슈 필드가 아니라 Projects v2 아이템
필드여서 `gh issue list` 결과에 **나오지 않는다.** 실제로 이것 때문에 In Progress 인 이슈를
착수 가능으로 잘못 안내한 적이 있다 (#65).

보드에 **올라오지 않은 열린 이슈**도 놓치지 말 것 — 보드에 없는 작업은 팀에게 존재하지 않으므로
그대로 보고해 카드를 올리게 한다.

## 2. 선행을 대조한다

각 이슈 본문의 `**선행**:` 줄을 읽어 거기 적힌 번호가 모두 `Done` 인지 확인한다.
선행은 `3.1`, `1.2.1` 처럼 **실행 계획 번호**로 적혀 있으므로 이슈 제목 앞의 번호로 맞춘다
(`6.x`, `2.x` 처럼 묶음 전체를 가리키기도 한다 — 그러면 그 묶음이 전부 닫혀야 한다).
`**선행**:` 줄이 아예 없으면 형식 위반이므로 정정 필요로 올린다.

## 3. 세 덩어리로 보고한다

| 덩어리 | 내용 |
|---|---|
| **착수 가능** | Status `Todo` + 선행 전부 Done. 이슈 번호·제목·선행 근거 |
| **대기 중** | 선행이 안 끝난 것. **무엇이 막고 있는지** 반드시 함께 적는다 |
| **정정 필요** | 아래 불일치. 착수 가능·불가로 분류하지 않는다 |

정정 필요로 올릴 것:

- Status 가 `In Progress` 인데 **담당자가 없다** — 누가 잡고 있는지 모른다
- 담당자가 있는데 Status 가 `Todo` — 착수 절차가 중간에 끊겼다
- 보드에 카드가 없는 열린 이슈
- `**선행**:` 줄이 없는 이슈

조용히 걸러 내지 않는다. 걸러 내면 목록에서 사라질 뿐 문제는 그대로 남는다.

**막고 있는 이슈가 여럿을 잠그고 있으면 그것을 짚어 준다.** 어디부터 풀어야 할지가 이 목록의
쓸모다.

## 4. 고치지 않는다

이 스킬은 **읽기만 한다.** 배정·Status 변경·브랜치 생성은 `/start-work` 의 일이고, 불일치를
발견해도 임의로 고치지 말고 보고만 한다 — 누가 무엇을 잡고 있는지는 사람이 안다.

이 파일과 `AGENTS.md` 의 내용이 다르면 `AGENTS.md` 를 따른다.
