# 착수 가능한 이슈 목록

판정 규칙의 정본은 `AGENTS.md` 의 **"작업 흐름 (요약)"** 절이다.
이 스킬과 어긋나면 `AGENTS.md` 를 따르고, 이쪽을 고친다.

## 실행

```bash
python .claude/skills/list-work/list_work.py
```

**직접 판정 코드를 짜지 않는다.** 이 스크립트를 쓴다. 매번 새로 짜면 규칙이 조금씩 달라지는데,
출력은 그럴듯해 보여서 틀린 걸 아무도 못 알아챈다. 실제로 그래서 진행 중인 이슈를
착수 가능으로 잘못 안내한 적이 있다 (#65).

출력을 그대로 붙여넣지 말고 **읽는 사람에게 필요한 형태로 정리해서** 보고한다.
특히 여럿을 잠그고 있는 병목 이슈는 짚어 준다 — 어디부터 풀어야 할지가 이 목록의 쓸모다.

## 출력 네 덩어리

| 덩어리 | 뜻 | 어떻게 다루나 |
|---|---|---|
| **착수 가능** | Status `Todo` + 선행 전부 `Done` | 그대로 보고 |
| **대기 중** | 선행이 안 끝났다. 막고 있는 이슈 번호가 함께 나온다 | 병목을 짚어 보고 |
| **정정 필요** | 절차가 끊겼거나 판정이 불가능하다 | **사람에게 보고만 한다. 임의로 고치지 않는다** |
| **보드에 없는 열린 이슈** | 카드가 안 올라갔다 | 보고해서 올리게 한다 |

담당자(assignee)는 판정에 쓰지 않는다. 배정과 Status 변경은 별개의 단계라 한쪽만 보면 어긋난다.

## 고치지 않는다

**읽기 전용이다.** 배정·Status 변경·브랜치 생성은 `/start-work` 의 일이다.
불일치를 발견해도 보고만 한다 — 누가 무엇을 잡고 있는지는 사람이 안다.

# 스크립트가 고장났을 때

고쳐도 된다. 단 **고친 뒤에는 반드시 자가 점검을 돌린다.**

```bash
python .claude/skills/list-work/list_work.py --selftest
```

판정 규칙 9가지를 가짜 데이터로 검사한다. 하나라도 `FAIL` 이면 종료 코드가 1이다.
규칙을 새로 만들거나 바꿨으면 `SELFTEST_CASES` 에 경우를 **추가**하고 고친다.

## 증상별로 어디를 보나

| 증상 | 원인 | 고칠 곳 |
|---|---|---|
| 멀쩡한 이슈가 "정정 필요 — 선행 N 을 찾지 못함" 으로 뜬다 | 이슈 **제목** 앞 계획번호를 못 읽었다 | 대개 이슈 제목이 규칙에서 벗어난 것이다. **스크립트보다 이슈 제목을 먼저 의심한다.** 제목 형식을 새로 허용해야 한다면 `build_plan_index()` |
| "묶음 N.x — 제목 번호를 못 읽은 이슈가 있어 판정 불가" | 그 묶음에 제목이 깨진 **열린** 이슈가 있다 | 해당 이슈 제목을 고치는 게 정석. 이건 오작동이 아니라 **의도된 안전장치**다 (아래 참고) |
| "본문에 `**선행**:` 줄이 없다" | 이슈 본문 형식 위반 | 이슈 본문. `AGENTS.md` 가 이 줄을 지우지 말라고 못 박고 있다 |
| 한글이 깨지거나 `UnicodeEncodeError` | Windows 콘솔 기본 cp949 | 이미 `sys.stdout.reconfigure` 로 막아 뒀다. 다시 나면 그 줄을 확인한다 |
| `gh` 관련 오류 | 로그인 안 됐거나 프로젝트 번호가 바뀜 | `gh auth status`, 파일 상단 `PROJECT` / `OWNER` 상수 |

## 고칠 때 지킬 것 하나

**판단이 서지 않으면 착수 가능으로 올리지 않는다.**

오답에는 두 방향이 있고 값이 다르다.

- 착수 가능인데 대기로 분류 — 일감 하나가 안 보일 뿐. 금방 드러나고 싸다
- 대기인데 착수 가능으로 분류 — 사람이 막힌 일을 잡고, **잡은 뒤에야** 막힌 걸 안다. 비싸다

그래서 `check_prereq()` 는 판정 불가일 때 `None` 을 돌려주고, 호출부는 그걸 **정정 필요**로
보낸다. 이 동작을 "너무 시끄럽다"는 이유로 완화하지 말 것. 한 번 완화했다가
막힌 이슈가 조용히 착수 가능으로 새어 나오면 이 스킬을 만든 이유가 사라진다.

시끄러움을 줄여야 한다면, 통과 기준을 느슨하게 하지 말고 **왜 판정이 안 되는지**를 없앤다
(= 이슈 제목·본문 형식을 고친다).
